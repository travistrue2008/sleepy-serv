# Request Flow

Route discovery is handled by the [plugin](./plugin.md), which scans the filesystem and builds a `RouteConfig` before `createApp` runs. The core pipeline receives pre-built routes: `buildRoutes` normalizes chains and prepends `mountPath`/middleware; when WebSocket support is enabled (`opts.ws` is truthy), `buildMergedRoutes` folds the reserved `/ws` handshake terminals into those chains; `buildModuleRoutes` wraps each chain in a `Bun.serve` handler → `buildServerRoutes` builds the route table; `buildServer` starts it (with a `websocket` handler only when WS is enabled).

## `res` is a threaded value, not a response

Middleware entries receive `(req, res, next)`; the terminal handler receives `(req, res)` with no `next` parameter (see [Middleware](./middleware.md) for the type distinction). `res` is the value handed to the current entry; `executeMiddlewareChain` starts it as `null` for the first middleware. Middleware do not mutate a shared object. Instead they pass data forward through `next(data)`: whatever is passed becomes the next entry's `res`, so a middleware can transform (e.g. the middleware from `parseJsonBody()` forwards the parsed body via `next(body)`) or extend it. Calling `next()` with no argument yields `undefined`, so forward the current value unchanged with `next(res)`. The actual HTTP response is the `Response` object a handler **returns**; returning a non-`Response` throws `TypeError`. The reserved `/ws` handshake terminals additionally read the value the terminal receives: `POST /ws` stores `res` on the ticket (as the session's `app` data) and returns it as the handshake `data` field (cached as `client.connectionData`); `PUT /ws/:clientId` preserves the existing session's `app` data and returns `res` as the response `data`. On these routes `res` is both the inbound threaded value and the outbound app-data channel (see [WebSocket Layer](./websocket.md)). Without middleware, `res` is `null` and no app data is stored on the ticket.

See also: [Overview](./overview.md), [Routing](./routing.md), [Middleware](./middleware.md), [TypeScript](../style/typescript.md) for how the `Middleware` and request types encode this model.
